# AutoHotkey

- Year: 2003
- Designer(s): Chris Mallett
- Paradigm(s): scripting, event-driven, procedural
- Family: scripting

## Problem It Aimed to Solve

For ordinary users on Windows who wanted to assign keyboard shortcuts, create macros, and automate GUI operations, most existing tools were either limited in functionality or difficult to use. Building on the syntax of its predecessor AutoIt while incorporating hotkey functionality at the core of the language, AutoHotkey aimed to make automating repetitive tasks and creating custom key bindings something anyone could do, without needing specialized programming knowledge.

## Features

- Assignment of scripts to hotkeys (key combinations) is built into the language as a first-class feature
- The text-replacement (hotstring) feature makes it easy to define mechanisms whereby typing a specific string automatically replaces it with another string
- Has a wide range of GUI automation features inherited from AutoIt, such as window detection/manipulation and key sending
- Scripts can be compiled into executable files for distribution
- From v2 onward, functions and object-oriented-style notation were strengthened, allowing more structured programs to be written

## Current Status

AutoHotkey is in active, widespread use. It has maintained high popularity for many years in the field of keyboard customization and business-process automation scripts among Windows users.

## Hello World

The `MsgBox` command, which displays a message box, is AutoHotkey's basic means of output.

```autohotkey
MsgBox, Hello, World!
```
