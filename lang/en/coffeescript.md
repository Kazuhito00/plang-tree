# CoffeeScript

- Year: 2009
- Designer(s): Jeremy Ashkenas
- Paradigm(s): scripting, functional
- Family: scripting

## Problem It Aimed to Solve

By the late 2000s, JavaScript was widely used as the standard language of the browser, but its syntactic weaknesses — semicolons, curly braces, the quirks of `var` declarations, and the confusing behavior of `this` — were frequently criticized as verbose and prone to tripping up developers. Jeremy Ashkenas thought that if code could be written in a concise, readable syntax reminiscent of Ruby and then compiled (transpiled) down to ordinary JavaScript, developers could improve their development experience alone while still using existing browsers and libraries as-is.

## Features

- A concise, indentation-based syntax that allows semicolons and curly braces to be omitted
- Expressive notations such as comprehensions and destructuring, derived from Ruby and Python
- High interoperability thanks to the plain, straightforward JavaScript code it outputs
- Provided features such as class syntax ahead of their time, before they existed in JavaScript itself
- Spread through integration into web frameworks, such as the Ruby on Rails asset pipeline

## Current Status

CoffeeScript is now "legacy." Its new adoption has declined substantially, both because JavaScript itself, from ES6 onward, absorbed features that CoffeeScript had anticipated, such as class syntax and arrow functions, and because of the rise of TypeScript. Nonetheless, it holds significant historical importance as an early effort to tackle the problem of improving the JavaScript development experience.
