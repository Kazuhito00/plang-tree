# Dyalog APL

- Year: 1983
- Designer(s): Peter Donnelly, John Scholes
- Paradigm(s): array, functional, object-oriented
- Family: numeric-scientific

## Problem It Aimed to Solve

At the time, in the 1980s, implementations of APL ran mainly on expensive mainframes, and there was demand for an affordable implementation that would run on microcomputers and the then-emerging Unix-family systems. Dyalog developed a commercial APL implementation that preserved the array-oriented expressiveness of Kenneth Iverson's APL while running on a broader range of platforms. It has since incorporated modern features such as object orientation, functional programming, and namespaces, and has served practical use in finance, insurance, and data analysis.

## Features

- Uses array-oriented notation inherited from APL, allowing bulk operations over entire arrays to be expressed concisely without writing loops
- Supports object-oriented programming, allowing code to be structured through namespaces
- Incorporates a functional programming style, allowing function composition through higher-order functions and operators
- Provided as a commercial implementation that runs across a wide range of platforms, from microcomputers to Unix-family systems
- Optimized for high-volume data processing in practical settings, such as data analysis and risk calculation in the finance and insurance industries

## Current Status

Dyalog APL is positioned as an active language, and continues to see real-world use today, particularly in finance, insurance, and data analysis. Thanks to ongoing development by Dyalog and community activity, it is among the most actively used implementations within the APL family today.
