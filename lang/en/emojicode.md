# Emojicode

- Year: 2016
- Designer(s): Theo Weidmann
- Paradigm(s): object-oriented, generic
- Family: esoteric

## Problem It Aimed to Solve

Whereas conventional programming languages assume alphabetic reserved words and identifiers, Emojicode arose from the experimental idea of using emoji themselves as keywords and type names, to express programs in a visual and humorous way. It is more than a mere joke, however: it implements modern language features such as object orientation, optional types, generics, closures, and protocols, compiling them to native code, reflecting a design that also aimed to hold up to practical use.

## Features

- Has its own syntax in which most keywords, type names, and operators are written as emoji
- Includes a full set of object-oriented features such as classes, protocols (interfaces), and extensions
- Expresses optional types via emoji, guaranteeing null-safety at the level of the type system
- Supports type parameterization through generics, allowing collections and the like to be handled in a type-safe manner
- Provides closures (lambda expressions) as a language feature
- Has a practically oriented implementation that compiles source code to native binaries via LLVM

## Current Status

Emojicode is positioned as a niche esoteric language and is not intended for practical use. It is valued for having implemented a modern type system and object-oriented features using nothing but emoji, and it continues to draw attention among esoteric-language enthusiasts and those interested in programming language design.
