# FLOW-MATIC

- Year: 1955
- Designer(s): Grace Hopper
- Paradigm(s): procedural
- Family: origin

## Problem It Aimed to Solve

In 1955, there was a demand for a language that could describe data processing in words close to English, so that business executives and clerical staff unfamiliar with mathematical notation could use it. FLOW-MATIC aimed to make business-processing programs easier to understand by clearly separating the definition of data from the processing procedure. Its designer, Grace Hopper, held a strong conviction that programs should not belong only to mathematicians, but should be close to a natural language that executives and clerical workers could also understand, and that philosophy runs through the entire design of this language. This attempt would go on to directly influence the design of COBOL.

## Features

- Describes processing using keywords close to English words, such as MOVE, COMPARE, and TRANSFER
- Has a structure that clearly separates the definition of data (the data division) from the processing procedure (the procedure division)
- Avoids mathematical symbols and specialized operators as much as possible, emphasizing plain English expressions
- Designed primarily for business processing and commercial data processing on the UNIVAC I/II
- Emphasizes practical clerical functions such as file reading/writing and report generation

## Languages It Was Influenced By

No direct linguistic ancestors have been identified.


## Languages It Influenced

Its direct influence on later languages appears to be limited.


## Current Status

Positioned as historical (a language that has finished its historical role). FLOW-MATIC itself is no longer used, but it occupies an important place in the history of computer science as the prototype from which COBOL was derived.
