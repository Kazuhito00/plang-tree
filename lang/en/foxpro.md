# FoxPro

- Year: 1984
- Designer(s): Fox Software
- Paradigm(s): procedural, object-oriented, query
- Family: domain-specific

## Problem It Aimed to Solve

dBase, as a pioneer of PC-based database management software, achieved widespread adoption, but its slow execution speed as an interpreted language and its lack of features for building large-scale business applications were pointed out as shortcomings.

Fox Software developed FoxPro as a product that maintained compatibility with dBase's .dbf format and command set while offering speed gains through compilation and a more advanced development environment (including a screen designer and report-building features). Maintaining compatibility so that existing dBase users could migrate easily was also an important goal for capturing the market.

## Features

- High compatibility with dBase's commands and data format (.dbf)
- Runs significantly faster than the interpreted dBase thanks to compiled execution
- Later versions incorporated an object-oriented class mechanism, allowing forms and controls to be reused as components
- Provides an RAD environment, including a screen designer and report builder, for visually assembling business applications
- Continued to be maintained for a long time as Visual FoxPro even after being acquired by Microsoft, and kept being used in business system development
- Table-manipulation syntax is built directly into the language, allowing SQL-like queries to be written

## Languages It Influenced

Its direct influence on later languages appears to be limited.


## Current Status

FoxPro is now a legacy language, and after Microsoft ended support for it, it has seen almost no adoption in new development, but it has a track record of having supported many small and medium-sized business systems from the 1990s through the 2000s. There remains some ongoing demand for maintaining old Visual FoxPro applications that are still running today.
