# JSFuck

- Year: 2012
- Designer(s): Martin Kleppe
- Paradigm(s): scripting
- Family: esoteric

## Problem It Aimed to Solve

JSFuck was created to demonstrate that, by exploiting the flexibility of JavaScript's implicit type coercion to its limit, arbitrary JavaScript code could be expressed using only six characters: `[ ] ( ) ! +`. The name derives from Brainfuck, and the technique inherits and extends the lineage of existing obfuscation methods such as jjencode from 2009. While it has practical security-related uses, such as evading browser filters, obfuscating code, and generating XSS attack payloads, it also carries a strong joke-like aspect that highlights the oddities of the JavaScript specification.

## Features

- Has the extreme constraint of allowing only six usable characters: `[`, `]`, `(`, `)`, `!`, and `+`
- Chains together implicit type coercion of arrays and booleans to build up numbers, strings, and arbitrary function calls entirely from scratch
- The generated code is orders of magnitude longer than the original JavaScript, making it effectively impossible for a human to read or write directly
- Normally produced by automatically converting original JavaScript code through a dedicated encoder rather than being hand-written
- Actually used in practice as an obfuscation and security payload technique to evade browsers' character filters and syntax checks
- Positioned within the joke-like tradition of obfuscated, esoteric languages that continues the lineage of Brainfuck and jjencode

## Current Status

JSFuck holds a niche position, mentioned as teaching material illustrating the oddities of JavaScript's type coercion and as an obfuscation technique in the security field. It is used almost entirely for evading browser filters or as a joke rather than as a practical programming language.

## Hello World

Because JSFuck builds arbitrary values from only the six characters `[]()!+`, a full "Hello, World!"-equivalent program would be impractically long to hand-write in an ordinary text editor (typically thousands of characters when generated by a dedicated encoder). As an example showing the core mechanism, here is the expression that represents the number 1 using only six characters.

```
+!+[]
```

This works by chaining implicit type coercions: converting the empty array `[]` to a number with unary plus yields `0`; `!+[]` (the logical negation of `0`) becomes the boolean `true`; and converting that back to a number with another unary plus yields `1`. An actual "Hello, World!" output is achieved by building up each character code one at a time in this manner and concatenating them.
