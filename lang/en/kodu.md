# Kodu

- Year: 2009
- Designer(s): Matt MacLaurin
- Paradigm(s): visual, event-driven, procedural
- Family: educational-visual

## Problem It Aimed to Solve

Kodu was developed by Matt MacLaurin and others at Microsoft FUSE Labs so that children with no programming experience could learn computational thinking through making games. Because text-based code is hard for beginners to grasp, Kodu adopted a visual, rule-based notation that expresses behavior as combinations of conditions and actions. By having users build games while moving characters ("bots") around in a 3D environment, it allowed abstract control structures to be learned experientially. It runs on both the Xbox 360 and Windows, and another notable feature is the ability to share created games within a community.

## Features

- Builds programs from combinations of visual rules in the form "WHEN condition DO action"
- Lets users place characters ("bots") and objects in a 3D space and build programs while getting immediate visual feedback
- Requires no text entry—programs are assembled purely by selecting icons—giving it an extremely low barrier to entry
- Runs on the Xbox 360 controller and on Windows PCs, so development can be completed with just a gamepad
- Lets users share created games and worlds with the community, and play or modify other users' creations
- Expresses concepts needed for game design—sensors, timers, scoring—as visual rules

## Current Status

Kodu is positioned for educational use and is not used for commercial game development. Official active development by Microsoft has ended, but the freely released software continues to be used in some communities and in STEM education settings.

## Hello World

Because Kodu is written using a visual, rule-based notation, the rule arrangement used in place of text code is shown here as pseudocode.

```
[WHEN game starts]
[DO say "Hello, World!"]
```
