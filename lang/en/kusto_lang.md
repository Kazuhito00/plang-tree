# KQL (Kusto Query Language)

- Year: 2019
- Designer(s): Microsoft
- Paradigm(s): declarative, query, dataflow
- Family: logic-declarative

## Problem It Aimed to Solve

Microsoft needed to analyze, with low latency and at high scale, the enormous volume of logs and telemetry data generated by its own cloud services. Conventional SQL for relational databases was not optimized for analytical workloads that make heavy use of time-series data and text search. So a new query language was designed for Azure Data Explorer (development codename Kusto) in which a pipe operator progressively narrows data down from a table. It retains concepts similar to SQL while placing extra emphasis on readability and analytical efficiency.

## Features

- A dataflow-style syntax in which the `|` (pipe) operator progressively filters and transforms data from a table
- Analytical operations expressed by chaining operators such as `where`, `summarize`, `project`, and `extend`
- Optimized for searching and aggregating large volumes of time-series log and telemetry data
- Full-text search operators (`has`, `contains`, and others) that make searching unstructured text easy
- Used as a common query language across multiple Microsoft products, including Azure Monitor, Application Insights, and Microsoft Sentinel

## Current Status

KQL is an actively used language today (status: active), remaining a standard query language across Microsoft's cloud monitoring and security product family, including Azure Data Explorer, Azure Monitor, and Microsoft Sentinel.
