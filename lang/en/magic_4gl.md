# Magic (4GL)

- Year: 1983
- Designer(s): David Assia, Yaki Dunietz, Jonathan Hashkes
- Paradigm(s): declarative, event-driven, visual
- Family: domain-specific

## Problem It Aimed to Solve

In the early 1980s, developing business applications required a cumbersome process involving compiling and linking, which tended to lengthen development cycles. Magic Software Enterprises adopted a metadata-driven application generation approach that required no compiling or linking and could be debugged immediately. Instead of coding logic, developers could build business applications simply by defining configuration (metadata). This approach accelerated the development of multi-platform business applications and evolved into the later Magic xpa platform.

## Features

- Has no compile or link step; applications run directly from metadata (configuration information) definitions
- Rather than conventional source code, the runtime interprets application behavior from definition information stored in a repository
- Adopts an event-driven model, declaratively describing processing that responds to screen operations and data changes
- Its visual development environment makes it easy even for non-programmers to configure business logic
- Designed from the outset for multi-platform support, ensuring portability across different OS and database environments
