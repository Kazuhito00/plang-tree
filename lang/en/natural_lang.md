# Natural

- Year: 1979
- Designer(s): Software AG
- Paradigm(s): procedural, declarative
- Family: domain-specific

## Problem It Aimed to Solve

Software AG needed a programming language for operating its own ADABAS database on mainframes with greater productivity. COBOL, the dominant language of the time, was verbose to write and posed challenges for development efficiency, creating demand for a fourth-generation language (4GL) that could build business applications with far less code. Natural was designed with built-in screen input/output facilities, supporting both interactive development and batch processing. It emerged as a competitor to COBOL, and in later years came to be positioned alongside Java as a service-description language as well.

## Features

- A fourth-generation language (4GL) designed on the premise of tight integration with the ADABAS database
- Built-in screen input/output (map) facilities that make it easy to build interactive mainframe applications
- Capable of expressing business logic with far less code than COBOL
- Able to express both batch processing and interactive (online) processing within the same language
- Later extended to target Java-based runtime environments, prolonging the life of legacy assets

## Current Status

Natural is positioned as a legacy language today (status: legacy), but it still runs in core systems at financial and insurance companies that continue to rely on ADABAS, and demand for its maintenance and migration continues. New development in the language is rarely seen, but given the scale of its existing installed base, maintenance is expected to continue for the foreseeable future.
