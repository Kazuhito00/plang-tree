# QuickBASIC

- Year: 1985
- Designer(s): Microsoft
- Paradigm(s): procedural
- Family: origin

## Problem It Aimed to Solve

GW-BASIC depended heavily on line numbers and GOTO statements, which meant that as programs grew larger, it became increasingly hard to follow the flow of execution—the "spaghetti code" problem. It was also an interpreter only, limiting execution speed. Microsoft developed QuickBASIC to enable structured programming via SUB/FUNCTION, to allow programs to be written without line numbers, and to raise both ease of development and execution speed by providing a compiler in addition to the interpreter.

## Features

- Named subroutines via SUB/FUNCTION enable structured programming that does not rely on line numbers
- User-defined types (TYPE) allow multiple pieces of data to be grouped together
- Supports both interactive development via the interpreter and generation of fast executable files via the compiler
- Comes with an integrated development environment (IDE) that allows debugging while editing code
- Improved graphics and disk I/O statements give it greater expressiveness than GW-BASIC

## Current Status

QuickBASIC is now positioned as a historical language (status: historical). It is remembered as an important branch point in the BASIC lineage, having given rise to two distinct directions—a lightweight educational version (QBasic) and a commercial visual development environment (Visual Basic).
