# Raku

- Year: 2000
- Designer(s): Larry Wall
- Paradigm(s): scripting, object-oriented, functional
- Family: scripting

## Problem It Aimed to Solve

In the early 2000s, years of feature additions had made Perl 5's internal implementation increasingly complex, and it was becoming clear that there were limits to retrofitting features that were beginning to be demanded at the time, such as asynchronous processing and syntactic extensibility. Larry Wall, without insisting on maintaining backward compatibility with the existing Perl 5, embarked on an ambitious plan (originally called Perl 6) to redesign from scratch a mechanism that let users extend the grammar itself, along with a more consistent type system and concurrency model. Development ended up taking far longer than originally anticipated.

## Features

- A powerful mechanism that allows the grammar itself to be extended in a macro-like way
- A gradual type system built in as a first-class citizen
- A model for concurrency and asynchronous processing integrated into the language specification
- Separation of specification and implementation, allowing multiple implementations
- An independent language with no direct compatibility with Perl

## Current Status

Raku currently holds a "niche" position. In 2019, it was formally renamed from its former name Perl 6 to Raku, establishing itself as a brand independent from Perl. Its long development period meant it missed the timing needed to gain momentum for widespread adoption, but it was an ambitious attempt to push forward advanced language features.
