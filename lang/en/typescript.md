# TypeScript

- Year: 2012
- Designer(s): Anders Hejlsberg
- Paradigm(s): object-oriented, functional
- Family: scripting

## Problem It Aimed to Solve

In the early 2010s, applications written in JavaScript were rapidly growing larger, but its dynamic typing led to frequent runtime errors from type inconsistencies, and it was difficult to support large-team development or IDE-based completion and refactoring assistance. Anders Hejlsberg, also the designer of C#, drew on his experience with large-scale web application development inside Microsoft and concluded that a mechanism was needed to catch type errors at compile time without sacrificing JavaScript's existing runtime environment and library assets.

## Features

- A superset of JavaScript, so existing JS code runs almost unchanged
- Gradual typing that allows types to be introduced incrementally
- Type system features inherited from C#, such as interfaces and generics
- Compiles (transpiles) down to ordinary JavaScript in the end
- Adopted as a standard by major frontend frameworks (Angular, React, and others)

## Current Status

TypeScript is currently "active" and has become the de facto standard language for frontend development. It has been widely embraced as a solution to the problem of type safety in ever-growing web application development, and its adoption continues to expand.
