# HCL

- 登場年: 2014年
- 設計者: Mitchell Hashimoto, Martin Atkins
- パラダイム: declarative
- 系統: domain-specific

## 解決したかった課題

HCL(HashiCorp Configuration Language)は、TerraformをはじめとするHashiCorp製ツール群のために作られた構成記述言語である。当時、インフラをコードで管理する際の設定フォーマットとしてJSONがよく使われていたが、JSONはコメントを書けず、末尾カンマの扱いも厳格で、人間が手で編集するには読みにくく書きにくいという問題があった。かといって汎用プログラミング言語をそのまま設定記述に使うと、学習コストが上がりすぎて構文も複雑になりすぎる。HashiCorpはこの中間、すなわち人間が読み書きしやすく、かつ機械にも扱いやすい構造化フォーマットを求めていた。さらに、JSONとの相互変換が可能であることも設計上の要件とされ、既存のJSONベースのツールチェーンとも共存できるようにする狙いがあった。

## 特徴

- ブロック構造(`resource "type" "name" { ... }`のような形式)によって階層的な設定を表現する
- コメント(`#`や`//`、`/* */`)が書けるなど、JSONにはない人間向けの利便性を備える
- 変数参照や式、条件分岐、for式によるループなど、宣言的でありながら一定のプログラマビリティを持つ
- HCLの構文木はJSONへの機械的な変換が可能であり、内部的にJSON表現とも等価に扱える
- Terraform、Packer、Vault、Consulなど複数のHashiCorp製品で共通の設定言語として採用されている
- チューリング完全な汎用言語ではなく、あくまで設定記述に特化したドメイン特化言語(DSL)である

## 現在の位置づけ

現役で広く使われている。特にTerraformを用いたIaC(Infrastructure as Code)の実践において、事実上の標準的な設定記述言語としての地位を確立しており、クラウドインフラの構築・管理の現場で日常的に利用されている。

## Hello World

HCLは設定記述言語であるため「実行して文字列を出力する」概念はないが、Terraformの出力値としてメッセージを定義する例を示す。

```hcl
output "hello" {
  value = "Hello, World!"
}
```
