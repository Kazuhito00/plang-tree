# occam

- 登場年: 1983年
- 設計者: David May(INMOS)
- パラダイム: concurrent, procedural
- 系統: concurrent-actor

## 解決したかった課題

1980年代初頭、英国の半導体企業INMOSは「トランスピュータ」と呼ばれる、複数個を接続して並列計算を行うことを前提としたマイクロプロセッサを開発していた。しかし当時の主流言語は基本的に逐次実行を前提としており、トランスピュータが持つ本来の並列処理能力を引き出すには不十分だった。David MayはTony Hoareが提唱した通信逐次プロセス(CSP)という並行計算の理論をほぼそのまま言語仕様に落とし込み、プロセス同士がチャネルを介して同期通信する「occam」を設計し、トランスピュータのハードウェア構造に直結した並列プログラミングを可能にした。

## 特徴

- CSP理論に基づき、独立したプロセスが明示的なチャネルを通じて同期的にメッセージをやり取りする
- `PAR`(並列実行)と`SEQ`(逐次実行)という構文により、並行性と逐次性を明示的に記述する
- トランスピュータのハードウェア(オンチップの通信リンク)と直接対応する設計になっている
- 変数のエイリアシングを厳しく制限し、プロセス間の意図しない副作用を防ぐ
- 言語仕様は小さく、教育・研究用途にも用いられた

## 現在の位置づけ

トランスピュータの商業的衰退とともにoccam自体は歴史的な言語となったが、CSPという理論を実際の言語として実装した先駆例として、並行プログラミング言語史における重要な位置を占めている。

## Hello World

```
#USE "course.lib"
PROC hello.world (CHAN BYTE scr!)
  SEQ
    out.string("Hello World!*n", 0, scr)
:
```
