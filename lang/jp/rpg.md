# RPG

- 登場年: 1959年
- 設計者: IBM
- パラダイム: procedural
- 系統: origin

## 解決したかった課題

1950年代の企業の経理・在庫管理業務では、パンチカードを機械的に集計するタビュレーティングマシン(パンチカード集計機)が広く使われていたが、配線盤の物理的な組み換えが必要で柔軟性に欠けていた。IBMはこれをコンピュータ上のプログラムで置き換えつつ、集計機の操作に慣れた事務員が、複雑な手続き型プログラミングを学ばなくても定型的な帳票(レポート)生成処理を定義できるようにしたいと考えた。

RPG(Report Program Generator)という名前が示す通り、入力仕様・計算仕様・出力仕様を表形式で指定するだけで帳票作成プログラムが生成される、業務に特化した設計になっている。これにより、既存の集計機オペレーターがそのままプログラム作成者へと移行しやすくなった。

## 特徴

- 入力・計算・出力の各仕様を固定書式の表形式で記述する独特のスタイル
- パンチカード集計機の操作感覚を引き継いだ、非プログラマにも扱いやすい設計
- 帳票生成・業務データ処理に特化しており汎用言語ではない
- IBMの中規模機(System/3、AS/400、現在のIBM iシリーズ)で標準的に使われてきた
- 後の版(RPG IVなど)ではより自由形式の構文や現代的な機能が追加された
- データベース(DB2 for i)との統合が強く、業務アプリケーション開発に特化した設計を保っている

## 現在の位置づけ

現在はレガシー言語として位置づけられている(status: legacy)が、IBM iシリーズ機を採用する企業の基幹業務システムでは今も現役で稼働しており、保守・更新の需要が続いている。

新規開発での採用は限られるものの、既存資産の規模が大きく、長期にわたり保守されると見られている。

## Hello World

RPG(RPG III/400世代)の固定書式では、演算仕様(C仕様)を決められた桁位置に記述する。`DSPLY`命令で画面に文字列を表示する、もっとも簡単な例を示す(桁位置の都合上、実際のソースでは列位置がさらに厳密に決まっている)。

```
     C           'HELLO'   DSPLY
     C                     RETRN
```
