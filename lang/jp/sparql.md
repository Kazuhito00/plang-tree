# SPARQL

- 登場年: 2008年
- 設計者: W3C
- パラダイム: declarative, query
- 系統: logic-declarative

## 解決したかった課題

2000年代、W3Cはウェブ上の情報を「意味」を持ったデータとして機械が解釈できるようにするセマンティックWebを提唱し、その基盤としてRDF(主語・述語・目的語からなるトリプル)という汎用データモデルを策定した。しかし、RDFグラフとして表現された分散データを実際に検索・結合するための標準的な問い合わせ手段がなければ、このモデルは実用にならなかった。

そこでW3Cは、リレーショナルDBにおけるSQLのような役割を果たす、グラフパターンマッチングに基づく標準クエリ言語としてSPARQLを策定した。異なる組織が公開する複数のRDFデータソースを、単一の問い合わせで横断的に扱えるようにすることも重要な目標だった。

## 特徴

- RDFのトリプル(主語・述語・目的語)をパターンとして記述し、それに合致するデータをグラフから検索する
- SELECT・WHERE句などSQLに類似した構文を持ち、SQL経験者が習得しやすい
- 複数のRDFデータソースを横断したフェデレーテッドクエリが可能
- グラフの結合・フィルタ・集約・ソートなど、リレーショナルクエリに近い操作をグラフデータに対して行える
- DBpediaやWikidataなどのナレッジグラフへの標準的なアクセス手段として使われる
- 結果をテーブル形式だけでなく、RDFグラフそのものとして構築(CONSTRUCT)することもできる

## 現在の位置づけ

SPARQLは現在も活発に使われており、DBpedia・Wikidataをはじめとするナレッジグラフや、セマンティックWeb・リンクトデータの分野で標準的な問い合わせ言語としての地位を保っている。近年はグラフデータベース全般への関心の高まりとともに、RDF以外のグラフストアでも類似の問い合わせ手法が注目されている。

## Hello World

SPARQLには標準出力の概念はなく、代わりにグラフパターンに合致する結果を返す問い合わせを実行する。`BIND`で文字列を変数に束縛し、それを`SELECT`で返す最小構成の例を示す。

```sparql
SELECT ?message
WHERE {
  BIND("Hello, World!" AS ?message)
}
```
