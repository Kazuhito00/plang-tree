# Umple

- 登場年: 2008年
- 設計者: Timothy Lethbridge, オタワ大学 Cruiseグループ
- パラダイム: object-oriented, declarative
- 系統: domain-specific

## 解決したかった課題

UML風のモデリング(クラス図、関連、状態機械など)とプログラミング言語のソースコードは長らく分断されており、設計図と実装コードを手作業で同期させ続けるのは大きな負担だった。IBM Rational Rose のような高価な専用モデリングツールへの依存も、モデル駆動開発(MDD)が実務で広く普及しない一因になっていたとされる。

Umpleは、オタワ大学電気電子・コンピュータ工学科のCruiseグループ(Timothy Lethbridge主導)が2008年に設計を開始した言語で、クラス、属性、関連(多重度付き)、状態機械といったUML的な構成要素をテキストとして直接記述し、それを既存のJava・C++・PHPのソースコードにそのまま混在させられるようにした。これにより、モデルとコードを別々の資産として管理するのではなく、1つのソースファイル群の中で統合的に扱えるようにすることを目指した。

## 特徴

- UMLのクラス図・状態機械などをテキスト表記で直接記述できる
- Java、C++、PHPへのコード生成に対応(Rubyは部分対応)
- 既存のJava/C++/PHPコードにUmple独自の構文をそのまま混在させられる
- デザインパターンの記述支援、不変性(immutability)制約、アスペクト指向的な機能を内蔵
- コンパイラ自体がUmpleで書かれた自己ホスト型処理系(「Umple自身が最大のテストケース」)
- MITライセンスで公開されているオープンソースプロジェクト

## 現在の位置づけ

Umpleは現在「niche」な位置づけで、主にオタワ大学のCruiseグループによるモデル駆動開発の研究・教育目的で使われ続けている。商用の大規模モデリングツールに代わる軽量なテキストベースの選択肢として、UML的なモデリングとコーディングを1つの作業に統合する試みは今も一定の関心を集めている。

Umpleコンパイラそのものがセルフホスト(Umpleで書かれている)であることは、この言語の実用性を示す象徴的な事実として、Wikipediaの記事でも特筆されている。

## Hello World

Wikipediaの記事に掲載されているUmpleのコード例は、Java互換の構文をそのまま許容する以下のようなものである(Umple独自のクラス図・状態機械構文を使わない最小例)。

```
class HelloWorld {
    public static void main(String [ ] args) {
        System.out.println("Hello World");
    }
}
```
