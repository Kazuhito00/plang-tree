# Vyper

- 登場年: 2017年
- 設計者: Vitalik Buterin
- パラダイム: procedural
- 系統: c-family

## 解決したかった課題

先行するスマートコントラクト言語Solidityは表現力が高い反面、継承や関数オーバーロード、複雑な修飾子といった機能が悪用されたり、意図しない挙動の温床になったりして、多くの脆弱性を生む原因となっていた。Vyperは、Pythonライクな読みやすい構文を採用しつつ、意図的に言語機能を削ぎ落とすことで、監査担当者がコードの挙動を確実に把握でき、悪用されにくい安全なスマートコントラクトを書けるようにすることを目指した。

## 特徴

- 継承、インラインアセンブリ、関数オーバーロード、演算子オーバーロードなど、誤用や脆弱性の元になりやすい機能を意図的にサポートしない
- Pythonに似たインデントベースの構文を採用し、読みやすさとコードレビューのしやすさを重視している
- 整数オーバーフロー検査やアクセス修飾子の明示など、安全性を高める仕組みが言語仕様に組み込まれている
- ループの上限が静的に決定できることを要求するなど、ガス代の見積もりやすさ・実行時間の予測可能性を重視した設計になっている
- イーサリアム仮想マシン(EVM)向けにコンパイルされ、Solidityと同じブロックチェーン基盤上で動作する

## 現在の位置づけ

現役で広く使われている。Solidityほどの普及率ではないものの、安全性を重視するプロジェクトやDeFi関連の一部コントラクトで採用が続いている。

## Hello World

Vyperのコントラクトでは、状態変数に文字列を格納し、`@view`が付与された関数でその値を返すのが典型的な記述となる。

```vyper
@external
@view
def hello() -> String[13]:
    return "Hello, World!"
```
